# NLLB 轻量术语处理

实现位于 `quant_scholar_translator/nllb_glossary.py`，默认启用。只对明确的英文到简体中文生效。它是推理前后的术语保护，不是微调，也不是将整个术语表塞入 NLLB 输入。

## 性能控制

- 七领域各 4 个规范词组，共 28 个白名单原词；译法与多词别名来自现有七领域 JSON，不维护第二套译法。
- 首次构建索引后缓存，合并词组匹配器、优先长词组，每段最多保护 4 处。
- 先保护公式、代码、数字和缩写。跳过多义项、需上下文消歧项和已知更具体词组的局部匹配。
- 正常路径只有一次 NLLB 推理，没有额外 Codex/Kimi 请求。
- 术语标记必须一一恢复；缺失、重复或未知标记会触发一次普通 NLLB 重试，并在当前服务进程内停用术语层。重启后才恢复尝试。
- 原有离线约束保持不变；离线模式不会因术语恢复失败而转网络翻译。

## 本机实测（2026-09-05）

使用已有 `nllb-200-distilled-600M-ct2` 模型、CTranslate2 CUDA，7 句七领域短句，每种模式 3 轮、21 次；交替测试顺序，严格离线，排除模型加载和预热。

| 项目 | 测量 |
|---|---:|
| 普通 NLLB 平均 / 中位数 | 104.58 / 101.15 毫秒 |
| 术语 NLLB 平均 / 中位数 | 216.24 / 206.33 毫秒 |
| 缓存后单次术语处理 | 0.0317 毫秒 |
| 首次术语索引构建 | 174.93 毫秒 |
| 模型初始化（不计入上述推理） | 5521.93 毫秒 |
| 因术语标记异常停用 | 否 |

这一组样本增加约 112 毫秒/句，推理约为普通模式的 2.07 倍。主要额外成本是标记占用模型 token，不是本地查词。实验中的短标记虽较快，但发生丢字和被译成自然语言的情况，未采用。

术语示例：`confidence interval` 从“信心间隔”变为“置信区间”；`maximum drawdown` 从错误译法变为“最大回撤”；`return value` / `garbage collection` 恢复为“返回值”/“垃圾回收”。但量化样本仍出现语序不自然，不能把术语正确等同于整句准确。

这不是端到端视频延迟，也不是 CPU、长段落、多会话并发或真实课程的全面基准。Whisper 分段、排队、模型冷启动等另有耗时。专业最终译文继续交给 Codex/Kimi，且只依据原文和上下文，不参考 NLLB 临时译文。

复现（项目根目录）：

```powershell
& '.\.venv\Scripts\python.exe' scripts/benchmark-nllb-glossary.py --rounds 3
```

脚本仅使用本地已下载模型，不会下载模型或启用网络回退，输出含时间和七组对照译文。

## 关闭开关

若更看重 NLLB 的最低延迟，可在启动本地翻译服务的同一 PowerShell 中设置：

```powershell
$env:QS_NLLB_GLOSSARY = 'off'
```

随后按原方式启动服务；已经运行的服务需重启才能读取。恢复时将值改为 `'on'`。这只是本终端及其子进程的环境设置，不修改系统配置。目前未增加浏览器菜单开关。
